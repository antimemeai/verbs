# 2026-11-23: scrap the design, keep the idea

The operator scrapped design/SPEC.md (the vlib + escape-check basics) and kept
the idea. The new direction is to be researched by lanes, then designed and
put before a tribunal. SPEC.md is marked superseded. My post-mortem is
papers/2026-11-23-old-design-postmortem.md.

## Operator decisions

- **Who and why.** Agents write the code. Habits such as "favor algebraic
  data types" and "use state machines" live today as prose doctrine. Verbs
  replaces that with mechanism: library constructs that carry the habit, and
  guards that notice questionable code. The guards raise findings through
  the compiler and clippy- or clang-tidy-style lints, the feedback agents
  already get. In the operator's words: "real mechanistic feedback/stops"
  instead of "a bonus doctrine".
- **Two tiers, with exact rules on top** (operator: "(b) as foundation with
  (c) layers on top"):
  - stops, where evidence is strong;
  - nudges, where code only looks questionable;
  - exact rules the operator would always accept, layered over both.
  The agent cannot ignore a nudge: it changes the code or records a reason
  at the site.
- **Zero tolerance is impossible.** Operator: "it's a nice thought but it's
  impossible." No tier promises zero false findings, stops included.
  Every finding needs a way past it with a reason. False findings found on
  the corpus are defects to fix, but none of this promises zero.
- **Habits.**
  - Start with three: favor ADTs, use state machines, use bounded types.
  - There is no master list; more are added as they occur.
  - Verbs must ship "really good mechanisms for encoding habits enumerated
    in the field", so adding a habit is ordinary work.
- **Languages.** C++ and Rust, and possibly others later ("etc.").

## My calls, stated to the operator

Headline findings:
- **C++ can own the whole loop.**
  - One ClangTidyCheck source ran unchanged under `clang-tidy -load` and in
    the compiler via `-fplugin`, with no measured compile-time cost on a
    small unit.
  - A 90-line plugin gave C++ Rust's `#[expect]` behavior. Its marker is a
    `[[clang::annotate("verbs.expect", habit, reason)]]` macro. Error-level
    findings can't be silenced by pragma or NOLINT, and a stale marker is
    reported.
  - NOLINT takes no reason and has no staleness check, so verbs must own
    the way past in C++.
- **Owned C++ constructs give good stops.**
  - A 30-line `vx::match` names the missing alternative in 1.7 KB of error
    text; `std::visit` gives 10.7 KB of libc++ internals.
  - A constexpr transition table checked by `consteval` names every missing
    (state, event) pair.
  - A 40-line `Bounded` rejects bad literals, raw ints and narrowing.
- **Rust is mostly native** (E0004, consuming-self typestate,
  `on_unimplemented`, `#[expect]`). But a library has no stable way to ship
  a lint: that needs nightly plus a rustc driver, owned or Dylint.
- **Nudge shapes measured 22–61% precision across habits.** Exceptions:
  - tagged unions: 10/10;
  - fields guarded in two or more methods: 5/6.
- **The starter habits reach at most 27% of 125 reviewer-found faults in
  the operator's agent-written code.**
  - State and lifecycle faults are the largest class a construct can stop,
    and they are high severity.
  - Strong IDs or captured origin, and obligation tokens, are the next
    candidates.
  - Weak test oracles and domain logic (48%) are beyond any habit.
- **There is field evidence that agents comply when a stop points at a
  type.** blackbird's swappable-parameters check stopped agent code 11
  times, and each fix introduced a type.

Open for the operator: the Rust lint host (an owned driver on nightly, or
Dylint), and whether state machines lead the starter habits. The design
synthesis follows.
